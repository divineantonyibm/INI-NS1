Use case 01

Interpret DNS Telemetry & Troubleshoot Issues

Scenario

A critical service starts failing to resolve for some users in one region. The operator has to work out which layer is at fault: NS1 health-check flapping, CDN edge degradation, nameserver rate limiting, or an upstream ISP BGP route flap. DNS and the underlay network are usually monitored in separate tools, so this takes a lot of manual cross-checking.

Persona and goal

Persona

NetOps / SRE, on call for the service

Secondary: network engineer

Goal

Find the real root cause in seconds, and avoid chasing the wrong layer.

Contribution of NS1 and INI

IBM NS1 Connect

Streams real-time query metrics, Pulsar latency feeds, Filter Chain execution logs and health monitor state changes to INI through MCP telemetry connectors.

IBM Network Intelligence

Uses time-series foundation models (Quantile, Prophet) to detect shifts from baseline. Correlates DNS anomalies with BGP flaps and interface congestion, and generates root-cause hypotheses.

Expected outcome

  • Faster detection and root-cause identification.
  • Fewer duplicate alerts, because related symptoms are grouped into one incident.

Use case 02

Plan and Execute DNS Changes

Scenario

An overloaded EU data center needs about 40% of its traffic moved to US East and APAC, and regional data-compliance rules still apply. Editing records by hand across several zones under pressure risks misconfiguration.

Persona and goal

Persona

Infrastructure architect, who approves and audits production changes

Secondary: SecOps / NOC

Goal

Carry out a multi-zone emergency migration without manual record edits.

Contribution of NS1 and INI

IBM NS1 Connect

Applies the approved Filter Chain weight updates, record changes and Pulsar steering overrides. Changes propagate across all global PoPs in under a second.

IBM Network Intelligence

Takes the engineer's intent from the Chat Assistant and drafts the plan with a multi-agent system. The Reasoning Agent builds the traffic-shifting plan, the RAG Agent checks it against change policies and runbooks, and the Function-Calling Agent produces the NS1 API payloads and rollback scripts. A person approves before anything runs.

Expected outcome

  • Faster, less error-prone changes with a full audit trail.

Measured by

Use case 03

Build Advanced Traffic Steering

Scenario

Architects setting up multi-CDN and hybrid-cloud steering have to balance several constraints at once: latency, committed transit billing, data sovereignty (GDPR) and origin capacity. Turning a business goal into the right Filter Chain is mostly trial and error.

Persona and goal

Persona

Infrastructure architect

Secondary: DevOps engineer

Goal

Turn a business routing goal into a Filter Chain that balances latency, transit cost, data sovereignty and origin capacity.

Contribution of NS1 and INI

IBM NS1 Connect

Provides the modular Filter Chain engine, Pulsar real-user monitoring feeds and real-time DNS decisioning at the global edge.

IBM Network Intelligence

Analyzes historical telemetry, egress costs, latency curves and capacity models, then recommends the Filter Chain order, for example UP/DOWN → SHED_LOAD → GEODNS → PULSAR → SELECT_FIRST_N. Saves proven patterns as reusable INI Skills.

Expected outcome

  • Lower latency and controlled transit cost.
  • Steering patterns that are consistent across squads.

Measured by

Design time from goal to approved chain Latency change after rollout Saved designs reused across squads
Use case 04

Validate Configurations Before Deployment

Scenario

A DevOps squad shifts weights on legacy origins for a flagship service. Without validation, a TTL caching issue or a Filter Chain logic bug could overwhelm a smaller secondary data center.

Persona and goal

Persona

Network engineer who owns the service and its change approvals

Secondary: SecOps

Goal

Show that a routing change is safe before it reaches production, with evidence a change board will accept.

Contribution of NS1 and INI

IBM NS1 Connect

Provides dry-run evaluation endpoints, virtual Filter Chain execution sandboxes and zone validation schemas to check syntax and semantics.

IBM Network Intelligence

Replays the previous 24 hours of real query telemetry against the proposed configuration using predictive models. Analyzes downstream capacity and produces a traffic heatmap, a blast-radius score and an explainable risk report.

Expected outcome

  • Fewer outages caused by configuration changes.
  • Quantified risk evidence for change boards, with a pipeline gate that blocks changes above the agreed threshold.

Measured by
